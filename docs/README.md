# Documentation

The repository documentation is organized by responsibility:

| Area | Purpose |
| --- | --- |
| `product/` | User problem, scope, requirements, and flows |
| `architecture/` | System boundaries, domain model, protocols, and integrations |
| `development/` | Setup, coding, testing, and release practices |
| `decisions/` | Versioned Architecture Decision Records |
| `roadmap.md` | Evidence-driven delivery stages |

Normative documents should have one clear responsibility. README files may summarize them, but behavior should be defined in requirements, architecture documents, schemas, or ADRs rather than duplicated in several places.

Stable domain names and serialized values are defined in [architecture/terminology.md](architecture/terminology.md).
